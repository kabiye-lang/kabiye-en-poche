# SPEC — Upgrade the mobile app to Expo SDK 58

Branch `chore/expo-sdk-58` from `develop`, worktree `.claude/worktrees/expo-sdk-58`.
Source: https://expo.dev/changelog/sdk-58 and https://docs.expo.dev/router/migrate/sdk-57-to-58/.

## Goal

Move `mobile/` from Expo SDK 57 (RN 0.86.3, React 19.2.3) to SDK 58 with no change in behaviour.
The app must build, start and work on iOS and Android as it does today.

The `bundledNativeModules.json` of the `expo` version the script picks is authoritative for
`react-native`, `react` and every bundled module. For `expo@58.0.11` it says `react-native 0.88.0`
and `react 19.3.0` (checked 2026-10-16 on unpkg). Record the exact versions in the report. A
pre-release (`-rc`) `react-native` is not acceptable: stop and report if the manifest names one.

Web is out of scope for behaviour. The app's web target is not shipped (`website/` is a separate
app). `+html.tsx` gets the SDK 58 contract so a web export still hydrates, and the web export must
compile (Done means 12). Web safe-area spacing (SDK 58 drops `react-native-safe-area-context` insets
on web) is not migrated.

## Decisions taken (owner, 2026-10-16)

1. Firebase: keep `@react-native-firebase/*`, and add a local config plugin that inserts
   `FirebaseApp.configure()` into the SDK 58 scene-based `AppDelegate.swift`. Reason: RNFB 26.4.0
   (latest) only matches `self.moduleName = "..."` or `factory.startReactNative(`, which the SDK 58
   template no longer contains, so prebuild logs "Unable to determine correct Firebase insertion
   point" and skips the call. The upstream fix (invertase PR #9336) is merged but not released.
2. OTA safety: bump the root `package.json` version `0.0.1` → `0.1.0`. Keep
   `runtimeVersion.policy: 'appVersion'`. Reason: every build so far has runtime `0.0.1`. Without a
   bump, a later JS-only push to `main` publishes an OTA for runtime `0.0.1`, which SDK 57 binaries
   would download.
3. Verification: free gates only. No EAS build, no `eas update`, no store submit.

## Mechanism

Use the repo's own updater, not `expo install --fix`. `mobile/` dependencies follow
`scripts/renovate.js` (see its comments): it locks to the current SDK major, so the major must be
set by hand first.

1. In `mobile/package.json` set `"expo": "58.0.0"`.
2. From the repo root run `node scripts/renovate.js`. It picks the newest stable `58.x` older than
   the `.ncurc.json` cooldown (`1d`; expected `58.0.11`) and rewrites:
   - every `bundledNativeModules` entry in `mobile/package.json`
   - `.ncurc.json` `reject`, `renovate.json` `ignoreDeps`
   - `pnpm-workspace.yaml` `minimumReleaseAgeExclude`
   Commit those generated changes as they come out. Do not hand-edit them.
3. Manual pins the script does not do:
   - `babel-preset-expo`: exact version that the chosen `expo` resolves (read it from
     `pnpm why babel-preset-expo -r` after install). Exactly one copy must remain.
   - `@react-native/jest-preset`: `^0.88.0`. `@react-native/eslint-config`: `^0.88.0`.
   - `jest`: `~30.x` (latest 30 minor), `@types/jest`: `^30.0.0`. `jest-expo@58` depends on jest-* 30.
     The jest-29 pin in memory is obsolete for SDK 58.
4. Install: `PATH=/opt/homebrew/bin:$PATH pnpm install` (regenerates `pnpm-lock.yaml`), then
   `rm -rf mobile/node_modules && PATH=/opt/homebrew/bin:$PATH pnpm install --frozen-lockfile`, then
   `PATH=/opt/homebrew/bin:$PATH pnpm check-duplicates`. Every pnpm command needs the PATH prefix
   (the `~/Library/pnpm/bin/pnpm` shim is broken).
5. Run `npx expo-doctor@latest` in `mobile/`. Fix what it reports, or record why an item is accepted.

## Firebase plugin — interface

`mobile/plugins/with-firebase-configure.js`, CommonJS, uses `withAppDelegate` from
`expo/config-plugins`. Pattern to copy for the plugin shape: RNFB's own
`node_modules/@react-native-firebase/app/plugin/build/ios/appDelegate.js` (`modifySwiftAppDelegate`).

Behaviour on `AppDelegate.swift` (Swift only; leave Objective-C untouched):
- If the contents already contain `FirebaseApp.configure()`, return them unchanged. This keeps it
  safe when RNFB ships #9336: a second `configure()` call throws at launch.
- Else ensure `import FirebaseCore` exists (RNFB 26.4.0 may already add it; never add it twice),
  and insert `FirebaseApp.configure()` on its own line immediately above the
  `return super.application(application, didFinishLaunchingWithOptions: launchOptions)` line inside
  `didFinishLaunchingWithOptions`, with matching indentation.
- If that anchor is not found, throw an error naming the file. A silent skip is the bug this
  plugin exists to prevent.
- Header comment: why it exists, link to invertase PR #9336, and "delete this plugin when
  `@react-native-firebase/app` ships the fix (check its prebuild output no longer warns)".

Unit test `mobile/__tests__/with-firebase-configure.test.ts` (pure logic, no native build): export the
string transform as a named function and test it against the SDK 58 `AppDelegate.swift` text
quoted in invertase issue #9331. Cases: inserts once; idempotent on second run; no duplicate import
when `import FirebaseCore` is present; throws when the anchor is missing.

## Edge cases

- Native folders: `ios/` and `android/` are gitignored (root `.gitignore` lines 11–12) and
  `git ls-files mobile/ios mobile/android` is empty, so `git status` cannot show them. The worktree
  is fresh, so `mobile/ios` does not exist there yet. Never delete the main checkout's `mobile/ios`.
  Verify cleanup with `test ! -e`, not `git status`.
- `expo prebuild` must run on a clean `mobile/ios` (the worktree has none) so `SceneDelegate.swift` is
  generated. Its log must contain no "Unable to determine correct Firebase insertion point" line
  that leaves `configure()` out: the generated `AppDelegate.swift` must contain exactly one
  `FirebaseApp.configure()`.
- Android: there is no committed `android/`. `expo run:android` generates it in the worktree.
  Delete it afterwards and check with `test ! -e mobile/android`.
- R8 is on in SDK 58 release builds. A local release build must compile and launch.
- `react-native-gesture-handler` 3: the app uses only `GestureHandlerRootView` (`src/app/_layout.tsx`).
- `react-native-webview` 14: one `WebView` in `src/screens/dictionary/dictionary-pdf.tsx`.
- RN 0.88 strict TypeScript API: deep `react-native/Libraries/*` imports are type errors. None exist
  today. Fix any ref-type errors `tsc` reports at the call site. Do not use the `customConditions`
  opt-out.
- Tabs: SDK 58 shows only declared screens. All five `(tabs)` routes are declared in
  `src/app/(tabs)/_layout.tsx`. Confirm in the smoke run that all five tabs appear.
- `uniwind` 1.12 peers `react-native >=0.81`. The installed range `^1.7.0` must resolve to a version
  that bundles with metro of SDK 58 (`check-duplicates` proves a single metro).
